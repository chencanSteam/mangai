# 平台网页端 — 访客监控

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 访客监控 |
| **页面入口** | `visitorMonitor` |
| **对应原型** | 平台网页端页面原型 |
| **页面类型** | 数据监控 / 全局统计 |
| **角色权限** | 平台管理员（运营/数据分析） |

---

## 2. 页面概述

访客监控页面是平台运营人员用于查看全局访问统计的核心工具。未登录访客不做用户级追踪，仅展示全局访问统计。页面以「全局访问概览 + 多维度热度排行」两层结构呈现，帮助运营团队了解平台整体活跃度、页面访问分布以及商品/内容的热度表现，从而优化内容推荐和运营策略。

运营人员可在本页快速查看平台核心访问指标，并通过页面浏览排行、热门商品收藏排行、热门帖子/案例浏览排行等维度，掌握平台当前最受欢迎的内容。

---

## 3. 功能描述

本页面核心功能包括：全局访问概览展示、页面浏览排行、热门商品收藏排行、热门帖子/案例浏览排行。

---

## 4. 功能分析

- **全局访问概览**：展示今日访客、总访问量、页面浏览总数、商品收藏总数等核心指标。
- **页面浏览排行**：以进度条形式展示平台内各页面的访问热度排名。
- **热门商品收藏排行**：展示平台内被收藏次数最多的商品排行。
- **热门帖子/案例浏览排行**：以表格形式展示帖子、案例等内容的浏览量排名。

---

## 6. 功能详细说明

### 6.1 全局访问概览

**用户场景**
运营人员打开访客监控页面，需要首先了解平台的整体访问规模与活跃情况。

**前置条件**
- 已进入访客监控页面。
- 各端页面已接入 `visitorStats` 统计体系，用户访问时自动触发 `trackPageView`。

**需求描述**
- 页面顶部展示全局访问数据概览卡片，包含以下核心指标：
  - **今日访客**：当日累计独立访客估算数，数据来源于 `visitorStats.todayVisits`。
  - **总访问量**：平台累计总访问次数，数据来源于 `visitorStats.totalVisits`。
  - **页面浏览总数**：平台所有页面的累计浏览量汇总，数据来源于 `visitorStats.pageViews` 各页面计数之和。
  - **商品收藏总数**：平台所有商品的累计收藏次数，数据来源于 `visitorStats.productCollections` 各商品计数之和。
- 指标数字采用大号统计样式展示，视觉层级清晰。

**后置条件**
- 运营人员可快速获取平台整体访问规模与活跃度。
- 访问数据为运营决策、资源调配、推广效果评估提供数据支撑。

**补充说明**
- 访客统计不做用户级追踪，仅做全局计数，不记录具体用户身份。
- 浏览次数在页面每次加载时累加，刷新即新增计数。
- 实际生产环境应接入后端分析平台，支持按时间段筛选、趋势对比等高级分析功能。

---

### 6.2 页面浏览排行

**用户场景**
运营人员想了解平台内哪些页面最受欢迎，以便优化页面资源和入口布局。

**前置条件**
- 页面已加载，`visitorStats.pageViews` 数据已初始化。

**需求描述**
- 在页面中部左侧（或上方）展示"页面浏览排行"卡片。
- 以排行列表形式展示页面名称、浏览次数和进度条。
- 进度条宽度按浏览量占比计算（`item.ratio%`）。
- 排行按浏览量降序排列，展示 Top N 页面。

**后置条件**
- 运营人员可直观看到各页面的相对热度。
- 根据页面热度调整运营资源投入和入口优先级。

**补充说明**
- 数据来源为 `visitorStats.pageViews` 对象，键为页面标识，值为浏览计数。
- 进度条为纯 CSS 实现，宽度为百分比值。

---

### 6.3 热门商品收藏排行

**用户场景**
运营人员需要掌握平台内商品的受关注程度，识别高潜商品和用户需求趋势。

**前置条件**
- 页面已加载，`visitorStats.productCollections` 数据已初始化。

**需求描述**
- 在页面中部展示"热门商品收藏排行"卡片。
- 以表格或列表形式展示商品名称、收藏次数。
- 排行按收藏量降序排列，展示 Top N 商品。
- 可展示商品所属品牌/分类信息，辅助分析品类热度。

**后置条件**
- 运营人员可查看热门商品的收藏排行。
- 为商品推荐、库存备货、营销活动提供数据依据。

**补充说明**
- 数据来源为 `visitorStats.productCollections` 对象，键为商品 SKU，值为收藏计数。
- 商品名称通过 SKU 匹配 `系统数据.products` 获取。

---

### 6.4 热门内容浏览排行

**用户场景**
运营人员需要掌握平台内具体内容的消费情况，识别高潜内容和长尾内容。

**前置条件**
- 页面已加载，`visitorStats.postViews` 和 `visitorStats.caseViews` 数据已初始化。

**需求描述**
- 在页面底部（或右侧）展示"热门内容浏览排行"卡片。
- 以表格形式展示内容类型、内容名称和浏览次数。
- 表格列：类型 | 内容 | 浏览。
- 内容类型包括帖子、案例等，合并展示并按浏览量统一排序。
- 展示 Top N 热门内容。

**后置条件**
- 运营人员可查看各类内容的消费排行。
- 为内容运营、社区活动策划、案例推荐提供数据支撑。

**补充说明**
- 帖子浏览数据来源为 `visitorStats.postViews`。
- 案例浏览数据来源为 `visitorStats.caseViews`。
- 内容名称通过 ID 匹配对应的数据源获取。

## 8. 备注

- 当前实现为前端静态原型，访客数据为预置 mock 数据，无真实用户行为采集。
- 未登录访客不做用户级追踪，仅做全局计数统计，不记录具体用户身份。
- 页面筛选和选中状态保存在全局 `state` 中，刷新页面后状态重置。
- 实际生产环境应接入后端分析平台，支持按时间段筛选、趋势对比、导出报表等高级功能。
