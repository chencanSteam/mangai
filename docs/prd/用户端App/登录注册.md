# 用户端 App — 登录注册

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 登录注册 |
| **页面路由/标识** | `auth`（状态 `userAuthMode` 控制） |
| **对应文件** | `assets/js/mobile-app.js`（`renderUserAuth()` 函数） |
| **页面类型** | 认证页 |
| **角色权限** | 普通用户 / 游客 |

---

## 2. 页面概述

登录注册是用户端 App 的**统一身份认证入口**。未登录用户进入 App 时默认展示此页面，支持多种登录与注册方式，满足不同场景下的用户接入需求。登录成功后，用户身份与偏好数据写入浏览器本地存储，并自动跳转至社区首页。

---

## 3. 功能描述

本页面提供账号密码登录、手机短信验证码登录、手机号注册、微信授权注册四种身份认证模式，并支持在各模式间快速切换。

---

## 4. 功能分析

- **账号密码登录**：输入手机号与密码完成登录。
- **手机短信登录**：通过手机号 + 短信验证码完成快捷登录。
- **手机号注册**：使用手机号、验证码、推荐码完成注册。
- **微信注册**：授权微信获取头像昵称后，补充手机号完成注册。
- **模式切换**：在各认证模式之间提供返回/切换入口。

---

## 5. 用户角色

| 角色/岗位名称 | 职责 | 权限 | 描述 |
|-------------|------|------|------|
| 普通用户 | 浏览/操作 | 全部功能 | 已登录用户 |
| 游客 | 浏览 | 部分功能受限 | 未登录用户，仅能查看登录注册页 |

## 6. 功能详细说明

### 6.1 账号密码登录

**用户场景**
用户已拥有平台账号，希望通过常规方式快速登录。

**前置条件**
- 用户处于未登录状态。
- 本地存储中无有效登录凭证（`mockUserAuth`）。

**需求描述**
- 页面顶部显示品牌标识「🏎️ 满改汽车改装平台」。
- 表单包含「手机号」与「密码」两个输入项。
- 手机号输入框默认填充示例值 `13800138000`。
- 密码输入框默认填充示例值 `mock1234`。
- 提交表单后，系统校验手机号与密码（mock 场景下默认通过），写入 `localStorage` 认证数据，跳转至社区首页。

**后置条件**
- 登录状态写入 `localStorage`（`mockUserAuth`）。
- 页面跳转至 `tab=forum`，并显示「已进入用户 App。」反馈。

**补充说明**
- 密码登录为默认展示模式（`mode === "login"`）。
- 底部提供「其他登录方式」分割线及快速切换入口。

---

### 6.2 手机短信登录

**用户场景**
用户忘记密码或希望免密快速登录。

**前置条件**
- 用户处于未登录状态。
- 已点击「手机短信登录」入口切换至该模式。

**需求描述**
- 页面标题为「手机短信登录」。
- 表单包含「手机号」和「验证码」两项。
- 手机号默认填充 `13800138000`，验证码默认填充 `888888`。
- 验证码输入框右侧提供「获取验证码」按钮（mock 场景下为纯 UI，不发真实短信）。
- 提交后校验手机号与验证码，完成登录并写入认证状态。

**后置条件**
- 与账号密码登录一致，写入认证状态并跳转首页。

**补充说明**
- 该模式通过 `data-user-auth-mode="smsLogin"` 触发切换。
- 底部提供「← 返回密码登录」按钮。

---

### 6.3 手机号注册

**用户场景**
新用户希望使用手机号完成平台注册。

**前置条件**
- 用户处于未登录状态。
- 已通过注册方式选择页或底部快捷入口进入手机号注册模式。

**需求描述**
- 页面标题为「手机号注册」。
- 表单包含「手机号」「验证码」「推荐码」三个字段。
- 手机号与验证码有默认示例值，推荐码为选填项。
- 提交后创建新用户档案，写入 `localStorage`，自动登录并跳转。
- 若填写了推荐码，系统会校验推荐码有效性（匹配 `MockData.providerInvites`）。

**后置条件**
- 新用户档案写入 `localStorage`（`mockUserAuth`）。
- 用户被标记为「自然流量」或对应服务商推荐来源。

**补充说明**
- 注册完成后，用户可直接使用全部 App 功能。
- 若推荐码无效，页面提示「推荐码无效，请确认后再注册」。

---

### 6.4 微信注册

**用户场景**
新用户希望通过微信授权快速完成注册，减少手动输入。

**前置条件**
- 用户处于未登录状态。
- 已进入微信注册模式（`mode === "registerWechat"`）。

**需求描述**
- 页面标题为「微信注册」。
- 首先提供「点击获取微信头像和昵称」按钮，点击后模拟获取微信用户信息（随机昵称 + 微信 OpenID）。
- 获取成功后展示微信头像（绿色渐变占位）、昵称及「重新获取」按钮。
- 下方表单需补充「手机号」「推荐码」「密码」。
- 提交后合并微信绑定信息完成注册，写入 `localStorage`。

**后置条件**
- 用户档案包含 `wechatOpenid` 与 `wechatNickname` 字段。
- 登录成功后跳转至社区首页。

**补充说明**
- 若未获取微信信息就提交表单，提示「请先获取微信头像和昵称」。
- 微信绑定信息存储在运行时状态 `state.wechatBindInfo` 中。

---

## 8. 备注

- 当前实现为前端静态原型，所有认证数据仅保存在当前浏览器 `localStorage` 中。
- 验证码与密码在 mock 场景下有预设默认值，方便演示快速登录。
- 微信授权为模拟实现，实际生产环境需接入微信 SDK 的 `wx.login` 与 `getUserInfo`。
