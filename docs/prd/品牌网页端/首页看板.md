# 品牌网页端 — 首页看板

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 品牌工作台 / 首页看板 |
| **页面入口** | `dashboard`（默认页） |
| **对应原型** | 品牌网页端页面原型 |
| **页面类型** | Dashboard（数据看板） |
| **角色权限** | 品牌运营人员 |

---

## 2. 页面概述

品牌工作台首页是品牌运营人员登录品牌网页端后的默认落地页。页面以「关键指标总览 + 待处理发货预览」为核心，帮助品牌方在一屏内快速掌握当前品牌的订单状态、商品上架情况和待发货任务，并通过快捷入口直接跳转至待发货处理页面。

该页面解决了品牌运营人员"每天登录后第一时间了解品牌经营概况和紧急待办"的需求，是品牌端最核心的信息聚合入口。

---

## 3. 功能描述

本页面核心功能包括：品牌关键指标展示、待发货订单预览、快捷跳转处理发货、操作反馈提示。

---

## 4. 功能分析

- **品牌指标总览**：展示当前品牌名称、待发货订单数、已发货订单数和上架商品数。
- **待处理发货预览**：展示前 4 条待发货订单的简要信息。
- **快捷跳转发货**：通过"处理发货"按钮快速跳转至待发货订单页面。
- **操作反馈展示**：顶部显示操作成功或失败的反馈消息。

## 6. 功能详细说明

### 6.1 品牌指标总览

**用户场景**
品牌运营人员每天登录后，想快速了解当前品牌的经营概况，包括有多少订单待发货、已发货多少、上架了多少商品。

**前置条件**
- 品牌运营人员已登录品牌网页端。
- 示例数据 中已定义品牌账号（品牌账号）、订单（订单列表）和商品（商品列表）数据。

**需求描述**
- 页面顶部展示 4 个指标卡片，横向排列：
 - **当前品牌**：展示品牌名称（如"BBS"）
 - **待发货订单**：统计当前品牌下未发货的订单数量
 - **已发货订单**：统计当前品牌下已发货的订单数量
 - **上架商品**：统计当前品牌下上架的商品数量
- 指标卡片采用统一的品牌端面板风格。

**后置条件**
- 运营人员可直观获取品牌的核心经营数据。

**补充说明**
- 品牌订单的筛选逻辑：订单的服务名称包含品牌名称，或包含该品牌下的任意商品名称。
- 发货状态通过 本地记录 中读取的 ship个人中心nt 数据与订单关联判断。

---

### 6.2 待处理发货预览

**用户场景**
品牌运营人员需要了解当前有哪些订单 urgent 需要发货，以便安排仓库和物流。

**前置条件**
- 已进入品牌工作台首页。

**需求描述**
- 指标卡片下方展示"待处理发货"板块。
- 板块头部包含：
 - 英文标签 `P结束ing
 - 中文标题 待处理发货
 - 右侧"处理发货"按钮（按钮-主色调）
- 表格/列表展示前 4 条待发货订单，每条展示：
 - 订单编号（ID）
 - 服务/商品名称（订单的service）
 - 用户名称（订单的用户）
 - 订单金额（订单的quote）
 - 订单状态（待发货）
 - 收件信息（收件人 / 电话 / 地址的拼接）
 - 每条右侧提供"去发货"按钮

**后置条件**
- 运营人员可预览 urgent 订单，点击"去发货"或"处理发货"跳转至待发货页面。

**补充说明**
- 待发货订单按时间倒序取前 4 条，若不足 4 条则展示实际数量。
- 收件信息通过 收件信息 函数拼接，兼容多种字段命名。

---

### 6.3 快捷跳转发货

**用户场景**
品牌运营人员看到有待发货订单后，想快速进入待发货订单列表进行批量处理。

**前置条件**
- 已在品牌工作台首页看到待处理发货板块。

**需求描述**
- 点击板块头部的"处理发货"按钮，页面切换至 待处理状态 标签页。
- 点击单条订单的"去发货"按钮，同样跳转至 待处理状态 标签页。

**后置条件**
- 页面切换至待发货订单页面，展示所有待发货订单的发货表单。

**补充说明**
- 跳转通过更新 当前页面 并调用 `r结束er` 重新渲染实现。

---

### 6.4 操作反馈展示

**用户场景**
品牌运营人员执行发货操作后，需要看到操作是否成功的提示。

**前置条件**
- 刚完成发货提交或其他操作。

**需求描述**
- 页面顶部（指标卡片上方）展示反馈提示条（`服务商-反馈）。
- 提示条内容为 当前页面 中的消息文本。
- 反馈消息在切换 标签页 时自动清空。

**后置条件**
- 用户可看到操作结果的即时反馈。

**补充说明**
- 反馈机制为前端状态管理，无后端消息推送。

## 7. 数据源

| 数据项 | 来源变量 | 来源文件 |
|--------|---------|---------|
| 品牌账号信息 | 数据的首个品牌账号 | 示例数据 |
| 品牌商品列表 | 数据的商品列表（过滤 品牌 字段） | 示例数据 |
| 品牌订单列表 | 数据的订单列表（关联商品/品牌名称过滤） | 示例数据 |
| 发货记录 | 本地记录.数据读取 | 本地记录 |
| 订单收件信息 | 订单的recipient / 订单的手机号 / 订单的地址 等 | 示例数据 |

---

## 8. 备注

- 当前为演示版本，品牌数据为预设示例数据，仅展示第一个品牌账号（首个品牌账号）。
- 发货状态通过 本地记录 持久化，刷新页面后发货记录保留。
- 品牌订单的匹配逻辑基于字符串包含判断（订单的service 是否包含品牌名或商品名），实际生产环境应通过品牌 ID 精确关联。
- 页面采用品牌端统一的浅色/中性主题风格。
