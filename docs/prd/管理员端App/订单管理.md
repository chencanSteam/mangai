# 管理员端 App — 订单管理

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 订单管理 |
| **页面路由/标识** | `orders` |
| **对应文件** | `assets/js/mobile-app.js`（`renderAdmin()` 函数中 `state.tab === "orders"` 分支） |
| **页面类型** | 列表管理 / 订单调度 |
| **角色权限** | 平台管理员（运营/客服） |

---

## 2. 页面概述

订单管理页面是平台管理员在移动端查看和处理全平台订单的核心页面。页面采用「分类 tab + 状态 tab + 订单卡片列表 + 内联详情展开」的多层结构，支持商品订单、服务订单、售后订单三类业务的查看和管理。管理员可在此查看订单详情、执行发货操作、分配服务订单给服务商、处理售后申请。

该页面解决了管理员"需要在移动端随时随地查看订单状态、处理 urgent 发货和派单"的场景需求。

---

## 3. 功能描述

本页面核心功能包括：订单分类切换（商品/服务/售后）、订单状态筛选、订单列表查看、订单详情展开、商品订单发货、服务订单派单、售后申请审核。

---

## 4. 功能分析

- **订单分类切换**：在商品订单、服务订单、售后订单之间切换。
- **订单状态筛选**：每个分类下有独立的状态筛选 tab。
- **订单卡片列表**：以卡片形式展示订单核心信息。
- **订单详情展开**：点击卡片选中订单，下方内联展开详情面板。
- **商品订单发货**：对待发货商品订单录入物流信息并确认发货。
- **服务订单派单**：将待分配服务订单指派给具体服务商。
- **售后申请处理**：对售后订单执行通过或驳回。

---

## 5. 用户角色

| 角色/岗位名称 | 职责 | 权限 | 描述 |
|-------------|------|------|------|

## 6. 功能详细说明

### 6.1 订单分类切换

**用户场景**
平台管理员需要查看不同类型的订单，例如商品销售订单或服务改装订单。

**前置条件**
- 已进入"订单"tab。

**需求描述**
- 页面顶部展示分类 tab 切换栏：
  - `goods` — 商品订单
  - `service` — 服务订单
  - `after-sale` — 售后订单
- 当前激活的分类高亮显示。
- 切换分类时，下方状态 tab 和订单列表同步更新。

**后置条件**
- 管理员可在三类订单之间切换查看。

**补充说明**
- 默认分类为 `service`（服务订单）。
- 分类状态保存在 `state.adminOrders.category` 中。

---

### 6.2 订单状态筛选

**用户场景**
平台管理员需要按订单状态筛选，例如只看"待发货"的商品订单或"待分配"的服务订单。

**前置条件**
- 已选择某个订单分类。

**需求描述**
- 分类 tab 下方展示当前分类对应的状态筛选 tab：

| 分类 | 状态选项 |
|------|---------|
| 商品订单 | 全部 / 待付款 / 待发货 / 待收货 / 已完成 |
| 售后订单 | 全部 / 待审核 / 已通过 / 已驳回 |
| 服务订单 | 全部 / 待分配 / 施工中 / 待验收 / 已完成 |

- 当前激活的状态高亮显示。
- 切换状态时，下方订单列表同步过滤更新。

**后置条件**
- 管理员可按状态快速定位目标订单。

**补充说明**
- 状态筛选逻辑由 `matchAdminOrderStatus()` 函数处理，支持多种状态匹配规则。
- 各分类的状态保存在独立的状态字段中（`goodsStatus` / `serviceStatus` / `afterSaleStatus`）。

---

### 6.3 订单卡片列表

**用户场景**
平台管理员需要一览当前分类和状态下的所有订单。

**前置条件**
- 已选择分类和状态。

**需求描述**
- 以纵向卡片列表展示过滤后的订单。
- 每张卡片包含：
  - **订单编号**（加粗）
  - **状态标签**（彩色标签）
  - **用户 / 车型**
  - **服务/商品名称**
  - **服务商**（服务订单）或 **支付状态 / 进度**（商品订单）
- 点击卡片可选中该订单，下方内联展开详情面板。
- 若当前无订单，展示空状态提示。

**后置条件**
- 管理员可浏览订单，选中后展开详情进行操作。

**补充说明**
- 商品订单通过 `isAdminGoodsOrder()` 判断（`type` 字段包含"商品"）。
- 售后订单通过 `afterSaleType` 字段判断。

---

### 6.4 订单详情展开（商品订单）

**用户场景**
平台管理员需要查看商品订单的完整信息并执行发货。

**前置条件**
- 已在商品订单列表中选中某订单。

**需求描述**
- 选中卡片下方内联展开详情面板（`renderAdminOrderDetail`）：
  - **英文标签**：`Goods Order`
  - **订单编号**
  - **基础信息键值对**：订单类型、用户、收货城市、商品、订单金额、支付状态、订单状态、履约进度、物流公司、物流单号、发货备注
  - **售后信息**（若存在售后）：售后类型、售后状态
  - **发货表单**（点击发货按钮后展开）：物流公司、物流单号、备注
  - **处理轨迹**：订单历史操作记录
  - **操作按钮区**：
    - 待发货状态："发货"按钮 → 展开发货表单 → "确认发货" / "取消"
    - 有售后申请："通过售后" / "驳回售后"
    - 其他状态：禁用按钮，显示跟进文案

**后置条件**
- 管理员可查看商品订单详情，执行发货或售后处理。

**补充说明**
- 发货表单由 `renderAdminShippingForm()` 渲染，提交后更新订单状态为"待收货"。
- 物流信息保存到订单对象的 `shippingCompany`、`shippingNo`、`shippingRemark` 字段。

---

### 6.5 订单详情展开（服务订单）

**用户场景**
平台管理员需要查看服务订单详情并将待分配订单派给服务商。

**前置条件**
- 已在服务订单列表中选中某订单。

**需求描述**
- 选中卡片下方内联展开详情面板：
  - **英文标签**：`Order Dispatch`（待分配）或 `Service Order`
  - **订单编号**
  - **基础信息键值对**：订单类型、用户、车辆、改装项目、报价金额、预约安装时间、服务商、当前进度
  - **推荐服务商列表**（仅待分配状态）：展示最多 3 个可接单的服务商，标注"客户意向门店"
  - **处理轨迹**
  - **操作按钮区**：
    - 待分配状态："查看详情" + "一键派给意向门店"
    - 点击推荐服务商卡片可直接派单给该服务商

**后置条件**
- 管理员可将服务订单指派给具体服务商。

**补充说明**
- 推荐服务商从 `providers` 中过滤，排除暂停接单和未通过审核的服务商。
- 派单后订单状态更新为"施工中"，并追加处理轨迹记录。

---

### 6.6 订单详情展开（售后订单）

**用户场景**
平台管理员需要查看售后申请详情并做出审核决策。

**前置条件**
- 已在售后订单列表中选中某订单。

**需求描述**
- 选中卡片下方内联展开详情面板：
  - **英文标签**：`After Sale`
  - **订单编号**
  - **基础信息键值对**：订单类型、用户、商品、订单金额、售后类型、售后原因、售后状态、申请时间
  - **处理轨迹**
  - **操作按钮区**：
    - 待平台审核状态："通过申请" / "驳回申请"
    - 已处理状态：禁用按钮

**后置条件**
- 管理员可审核售后申请，更新售后状态。

**补充说明**
- 售后通过/驳回后，订单状态更新为"已完成"，并生成处理轨迹和用户反馈消息。

---

### 6.7 商品订单发货

**用户场景**
平台管理员需要对已付款的商品订单执行发货操作，录入物流信息。

**前置条件**
- 已选中待发货的商品订单，点击"发货"按钮。

**需求描述**
- 点击"发货"后，详情面板内展开发货表单。
- 表单字段：
  - 物流公司（默认"顺丰速运"）
  - 物流单号（必填）
  - 发货备注（默认"木箱加固包装，签收前请先检查外箱。"）
- 点击"确认发货"后：
  - 保存物流信息到订单对象
  - 更新订单状态为"待收货"
  - 追加处理轨迹
  - 收起发货表单

**后置条件**
- 订单状态更新，用户可在前端看到物流信息。

**补充说明**
- 发货表单提交由 `handleAdminShippingSubmit()` 处理。
- 当前为前端状态更新，实际应调用物流发货接口。

---

### 6.8 服务订单派单

**用户场景**
平台管理员将用户的服务订单分配给合适的服务商进行施工。

**前置条件**
- 已选中待分配的服务订单。

**需求描述**
- 展示推荐服务商列表，每个服务商卡片包含名称和城市。
- 若某服务商是客户意向门店，标注"客户意向门店"。
- 点击推荐服务商卡片，订单指派给该服务商。
- 点击"一键派给意向门店"，直接指派给 `order.intention` 指定的服务商。
- 派单后：
  - 更新 `order.provider` 为服务商名称
  - 更新 `order.status` 为"施工中"
  - 更新 `order.progress` 为派单说明
  - 追加处理轨迹

**后置条件**
- 订单分配给服务商，服务商可在服务商端看到新订单。

**补充说明**
- 派单为即时生效（前端内存），实际应调用派单接口并通知服务商。

## 8. 备注

- 当前实现为前端静态原型，订单发货、派单、售后审核仅修改内存数据。
- 移动端订单管理适合处理简单、urgent 的操作（如发货、派单），复杂的订单分析和批量操作建议在网页端完成。
- 发货表单的物流公司和单号为手动录入，实际生产环境应支持扫描快递单号自动识别物流公司。
- 售后审核目前只支持通过/驳回两种结果，实际应支持更细粒度的处理（如部分退款、换货等）。
