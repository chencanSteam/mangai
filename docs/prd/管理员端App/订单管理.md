## 一、引言

### 1、编写目的

订单管理页面是平台管理员在移动端查看和处理全平台订单的核心页面。页面采用「分类 标签页 + 状态 标签页 + 订单卡片列表 + 内联详情展开」的多层结构，支持商品订单、服务订单、售后订单三类业务的查看和管理。管理员可在此查看订单详情、执行发货操作、分配服务订单给服务商、处理售后申请。

该页面解决了管理员"需要在移动端随时随地查看订单状态、处理 紧急 发货和派单"的场景需求。

### 2、背景

满改平台是一个高端汽车改装服务系统，涵盖用户端 App、服务商端 App、平台网页端、品牌网页端和管理员端 App。

---

## 二、任务概述

### 1、产品定位

满改平台是面向高端汽车改装领域的综合服务平台，连接车主用户、改装服务商和品牌供应商，提供从内容种草、方案咨询、商品采购到施工履约的一站式改装服务。

### 2、产品目标

通过平台化运营，提升改装行业的服务标准化水平和交易透明度，降低用户决策成本，帮助服务商拓展客源，实现多方共赢。

### 3、目标用户与使用场景

目标用户包括：有改装需求的车主、提供改装服务的服务商门店、管理平台的运营人员、品牌供应商。

### 4、用户的特点

车主用户注重改装品质与安全性，决策周期较长，需要案例参考和专业建议。服务商关注订单获取效率与结算周期。

### 5、岗位与角色

| 角色/岗位名称 | 职责 | 权限 | 描述 |
| ------ | ------ | ------ | ------ |
| 平台管理员 | 全平台订单调度、异常处理 | 查看全部订单、执行发货/派单/售后审核 | 统筹订单履约，处理异常和 紧急 订单 |
| 平台客服 | 发货处理、售后跟进 | 查看商品订单和售后订单、执行发货和售后审核 | 专注商品履约和售后服务 |
| 平台管理员 | 服务订单派单跟踪 | 查看服务订单、执行派单 | 专注服务订单的派单和施工跟踪 |

## 五、功能需求

### 1、功能描述

本页面核心功能包括：订单分类切换（商品/服务/售后）、订单状态筛选、订单列表查看、订单详情展开、商品订单发货、服务订单派单、售后申请审核。

### 2、功能分析

· **订单分类切换**：在商品订单、服务订单、售后订单之间切换。
· **订单状态筛选**：每个分类下有独立的状态筛选 标签页。
· **订单卡片列表**：以卡片形式展示订单核心信息。
· **订单详情展开**：点击卡片选中订单，下方内联展开详情面板。
· **商品订单发货**：对待发货商品订单录入物流信息并确认发货。
· **服务订单派单**：将待分配服务订单指派给具体服务商。
· **售后申请处理**：对售后订单执行通过或驳回。

### 3、用户角色

| 角色/岗位名称 | 职责 | 权限 | 描述 |
| ------ | ------ | ------ | ------ |
| 平台管理员 | 全平台订单调度、异常处理 | 查看全部订单、执行发货/派单/售后审核 | 统筹订单履约，处理异常和 紧急 订单 |
| 平台客服 | 发货处理、售后跟进 | 查看商品订单和售后订单、执行发货和售后审核 | 专注商品履约和售后服务 |
| 平台管理员 | 服务订单派单跟踪 | 查看服务订单、执行派单 | 专注服务订单的派单和施工跟踪 |

### 5、功能详细说明

#### 5.1 订单分类切换

**用户场景**

平台管理员需要查看不同类型的订单，例如商品销售订单或服务改装订单。

**前置条件**

- 已进入"订单"标签页。

**需求描述**

- 页面顶部展示分类 标签页 切换栏：
 - — 商品订单
 - — 服务订单
 - — 售后订单
- 当前激活的分类高亮显示。
- 切换分类时，下方状态 标签页 和订单列表同步更新。

**后置条件**

- 管理员可在三类订单之间切换查看。

**补充说明**

- 默认分类为 （服务订单）。
- 分类状态保存在 当前页面 中。

---

#### 5.2 订单状态筛选

**用户场景**

平台管理员需要按订单状态筛选，例如只看"待发货"的商品订单或"待分配"的服务订单。

**前置条件**

- 已选择某个订单分类。

**需求描述**

- 分类 标签页 下方展示当前分类对应的状态筛选 标签页：

| 分类 | 状态选项 |
|------|---------|
| 商品订单 | 全部 / 待付款 / 待发货 / 待收货 / 已完成 |
| 售后订单 | 全部 / 待审核 / 已通过 / 已驳回 |
| 服务订单 | 全部 / 待分配 / 施工中 / 待验收 / 已完成 |

- 当前激活的状态高亮显示。
- 切换状态时，下方订单列表同步过滤更新。

**后置条件**

- 管理员可按状态快速定位目标订单。

**补充说明**

- 状态筛选逻辑由匹配管理员订单状态映射处理，支持多种状态匹配规则。
- 各分类的状态保存在独立的状态字段中（商品状态 / 服务状态 / 售后状态）。

---

#### 5.3 订单卡片列表

**用户场景**

平台管理员需要一览当前分类和状态下的所有订单。

**前置条件**

- 已选择分类和状态。

**需求描述**

- 以纵向卡片列表展示过滤后的订单。
- 每张卡片包含：
 - **订单编号**（加粗）
 - **状态标签**（彩色标签）
 - **用户 / 车型**
 - **服务/商品名称**
 - **服务商**（服务订单）或 **支付状态 / 进度**（商品订单）
- 点击卡片可选中该订单，下方内联展开详情面板。
- 若当前无订单，展示空状态提示。

**后置条件**

- 管理员可浏览订单，选中后展开详情进行操作。

**补充说明**

- 商品订单通过 商品订单判断 判断（类型 字段包含"商品"）。
- 售后订单通过 售后类型 字段判断。

---

#### 5.4 订单详情展开（商品订单）

**用户场景**

平台管理员需要查看商品订单的完整信息并执行发货。

**前置条件**

- 已在商品订单列表中选中某订单。

**需求描述**

- 选中卡片下方内联展开详情面板（订单详情面板）：
 - **标签**：商品订单
 - **订单编号**
 - **基础信息键值对**：订单类型、用户、收货城市、商品、订单金额、支付状态、订单状态、履约进度、物流公司、物流单号、发货备注
 - **售后信息**（若存在售后）：售后类型、售后状态
 - **发货表单**（点击发货按钮后展开）：物流公司、物流单号、备注
 - **处理轨迹**：订单历史操作记录
 - **操作按钮区**：
 - 待发货状态："发货"按钮 → 展开发货表单 → "确认发货" / "取消"
 - 有售后申请："通过售后" / "驳回售后"
 - 其他状态：禁用按钮，显示跟进文案

**后置条件**

- 管理员可查看商品订单详情，执行发货或售后处理。

**补充说明**

- 发货表单由 渲染，提交后更新订单状态为"待收货"。
- 物流信息保存到订单对象的 物流公司、物流单号、发货记录标记 字段。

---

#### 5.5 订单详情展开（服务订单）

**用户场景**

平台管理员需要查看服务订单详情并将待分配订单派给服务商。

**前置条件**

- 已在服务订单列表中选中某订单。

**需求描述**

- 选中卡片下方内联展开详情面板：
 - **标签**：（待分配）或服务订单
 - **订单编号**
 - **基础信息键值对**：订单类型、用户、车辆、改装项目、报价金额、预约安装时间、服务商、当前进度
 - **推荐服务商列表**（仅待分配状态）：展示最多 3 个可接单的服务商，标注"客户意向门店"
 - **处理轨迹**
 - **操作按钮区**：
 - 待分配状态："查看详情" + "一键派给意向门店"
 - 点击推荐服务商卡片可直接派单给该服务商

**后置条件**

- 管理员可将服务订单指派给具体服务商。

**补充说明**

- 推荐服务商从 服务商列表 中过滤，排除暂停接单和未通过审核的服务商。
- 派单后订单状态更新为"施工中"，并追加处理轨迹记录。

---

#### 5.6 订单详情展开（售后订单）

**用户场景**

平台管理员需要查看售后申请详情并做出审核决策。

**前置条件**

- 已在售后订单列表中选中某订单。

**需求描述**

- 选中卡片下方内联展开详情面板：
 - **标签**：售后
 - **订单编号**
 - **基础信息键值对**：订单类型、用户、商品、订单金额、售后类型、售后原因、售后状态、申请时间
 - **处理轨迹**
 - **操作按钮区**：
 - 待平台审核状态："通过申请" / "驳回申请"
 - 已处理状态：禁用按钮

**后置条件**

- 管理员可审核售后申请，更新售后状态。

**补充说明**

- 售后通过/驳回后，订单状态更新为"已完成"，并生成处理轨迹和用户反馈消息。

---

#### 5.7 商品订单发货

**用户场景**

平台管理员需要对已付款的商品订单执行发货操作，录入物流信息。

**前置条件**

- 已选中待发货的商品订单，点击"发货"按钮。

**需求描述**

- 点击"发货"后，详情面板内展开发货表单。
- 表单字段：
 - 物流公司（默认"顺丰速运"）
 - 物流单号（必填）
 - 发货备注（默认"木箱加固包装，签收前请先检查外箱。"）
- 点击"确认发货"后：
 - 保存物流信息到订单对象
 - 更新订单状态为"待收货"
 - 追加处理轨迹
 - 收起发货表单

**后置条件**

- 订单状态更新，用户可在前端看到物流信息。

**补充说明**

- 发货表单提交由 处理最小S发货提交 处理。
- 当前为前端状态更新，实际应调用物流发货接口。

---

#### 5.8 服务订单派单

**用户场景**

平台管理员将用户的服务订单分配给合适的服务商进行施工。

**前置条件**

- 已选中待分配的服务订单。

**需求描述**

- 展示推荐服务商列表，每个服务商卡片包含名称和城市。
- 若某服务商是客户意向门店，标注"客户意向门店"。
- 点击推荐服务商卡片，订单指派给该服务商。
- 点击"一键派给意向门店"，直接指派给 订单的意向 指定的服务商。
- 派单后：
 - 更新 订单的服务商 为服务商名称
 - 更新 状态 为"施工中"
 - 更新 订单的进度 为派单说明
 - 追加处理轨迹

**后置条件**

- 订单分配给服务商，服务商可在服务商端看到新订单。
