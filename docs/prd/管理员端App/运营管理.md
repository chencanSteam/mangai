# 管理员端 App — 运营管理

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 运营管理 |
| **页面入口** | `operations` |
| **对应原型** | 用户端 App 页面原型 |
| **页面类型** | 内容审核 / 社区管理 |
| **角色权限** | 平台管理员（运营） |

---

## 2. 页面概述

运营管理页面是平台管理员在移动端处理案例审核和论坛内容审核的核心页面。页面以「子 tab 切换 + 卡片列表 + 内联详情展开」的结构呈现，分为"案例审核"和"论坛处理"两个子视图。管理员可在此审核服务商提交的案例、处置违规帖子和评论，维护平台内容质量和社区氛围。

该页面解决了管理员"需要在移动端随时随地完成内容审核和社区治理"的场景需求，是平台 UGC 生态健康运营的重要保障。

---

## 3. 功能描述

本页面核心功能包括：案例审核列表查看、案例审核操作（通过/展示/驳回）、论坛帖子列表查看、帖子状态管理（删除/恢复）、评论区管理（删除/恢复评论）。

---

## 4. 功能分析

- **子 tab 切换**：在"案例审核"和"论坛处理"之间切换。
- **案例审核列表**：展示所有案例，支持点击选中展开详情。
- **案例审核操作**：对案例执行审核通过、设为正常展示、审核驳回。
- **论坛帖子列表**：展示所有帖子，支持点击选中展开详情。
- **帖子状态切换**：删除或恢复帖子。
- **评论管理**：删除或恢复单条评论。

---

## 5. 用户角色

| 角色/岗位名称 | 职责 | 权限 | 描述 |
|-------------|------|------|------|

## 6. 功能详细说明

### 6.1 子 tab 切换

**用户场景**
平台管理员需要在案例审核和论坛处理之间切换。

**前置条件**
- 已进入"运营"tab。

**需求描述**
- 页面顶部展示子 tab 切换栏：
  - `cases` — 案例审核
  - `forum` — 论坛处理
- 当前激活的 tab 高亮显示。
- 切换 tab 时，下方列表重新渲染，已选中的项重置。

**后置条件**
- 管理员可在案例审核和论坛处理两个视图间切换。

**补充说明**
- 默认子 tab 为 `cases`（案例审核）。
- 从工作台首页的"待审核案例"或"待处理论坛"快捷入口进入时，自动切换至对应子 tab。

---

### 6.2 案例审核列表

**用户场景**
平台管理员需要查看所有服务商提交的案例，识别优质内容进行展示推荐，或发现违规/低质内容进行驳回。

**前置条件**
- 已切换至"案例审核"子 tab。

**需求描述**
- 以纵向卡片列表展示所有案例。
- 每张卡片包含：
  - **案例标题**（加粗）
  - **车型 / 改装类型 / 服务商**
  - **审核状态标签**（如"待审核"、"已通过"，彩色标签）
  - **展示状态标签**（如"正常展示"、"未展示"，`pill` 样式）
- 点击卡片可选中该案例，下方内联展开详情面板。
- 当前选中的卡片高亮显示（`active` 类）。

**后置条件**
- 管理员可浏览案例，选中后展开详情进行审核操作。

**补充说明**
- 审核状态使用 `nCaseAudit()` 函数映射。
- 展示状态使用 `nCaseDisplay()` 函数映射。

---

### 6.3 案例详情与审核操作

**用户场景**
平台管理员需要查看案例的完整信息并做出审核决策。

**前置条件**
- 已在案例审核列表中选中某案例。

**需求描述**
- 选中卡片下方内联展开详情面板（`renderAdminCaseDetail`）：
  - **英文标签**：`Case Review`
  - **案例标题**
  - **基础信息键值对**：服务商、车型、风格、改装类型、花费区间、审核状态、展示状态
  - **资料清单**：案例主图、施工过程图、完工对比图（占位展示）
  - **操作按钮区**：
    - "审核通过"（`btn btn-primary`）
    - "设为正常展示"（`btn btn-secondary`）
    - "审核驳回"（`btn btn-danger`）

**审核操作逻辑**：
- **审核通过**：更新案例 `audit = "已通过"`
- **设为正常展示**：更新案例 `audit = "已通过"`，`display = "正常展示"`
- **审核驳回**：更新案例 `audit = "已驳回"`，`display = "未展示"`

**后置条件**
- 审核结果更新到内存数据中，列表同步刷新。

**补充说明**
- 当前为前端状态修改，无后端接口调用。
- "设为正常展示"相当于"审核通过 + 直接上架"的组合操作。

---

### 6.4 论坛帖子列表

**用户场景**
平台管理员需要查看社区内的帖子，发现违规内容或处理用户举报。

**前置条件**
- 已切换至"论坛处理"子 tab。

**需求描述**
- 以纵向卡片列表展示所有帖子。
- 每张卡片包含：
  - **帖子标题**（加粗）
  - **作者 / 发布时间**
  - **互动数据**：回复数、点赞数、浏览量（`pill` 样式）
  - **帖子状态标签**（如"正常"、"已删除"，彩色标签）
- 点击卡片可选中该帖子，下方内联展开详情面板。

**后置条件**
- 管理员可浏览帖子，选中后展开详情进行内容管理操作。

**补充说明**
- 帖子状态使用 `nForum()` 函数映射。
- 浏览量使用 `toLocaleString("zh-CN")` 格式化千分位。

---

### 6.5 帖子详情与状态管理

**用户场景**
平台管理员需要查看帖子的完整信息、评论区，并执行删除或恢复操作。

**前置条件**
- 已在论坛处理列表中选中某帖子。

**需求描述**
- 选中卡片下方内联展开详情面板（`renderAdminForumDetail`）：
  - **英文标签**：`Forum Moderation`
  - **帖子标题**
  - **基础信息键值对**：作者、发布时间、当前状态、互动数据
  - **操作按钮区**：
    - "删除帖子" / "恢复帖子"（根据当前状态动态切换，`btn btn-primary`）
  - **评论区**：
    - 展示该帖子下的所有评论列表
    - 每条评论展示：作者、状态标签、评论内容
    - 每条评论右侧提供"删除评论" / "恢复评论"按钮

**帖子操作逻辑**：
- 点击"删除帖子"：更新帖子 `status = "已删除"`
- 点击"恢复帖子"：更新帖子 `status = "正常"`

**评论操作逻辑**：
- 点击"删除评论"：更新评论 `status = "已删除"`
- 点击"恢复评论"：更新评论 `status = "正常"`

**后置条件**
- 帖子或评论状态更新，列表同步刷新。

**补充说明**
- 评论数据来自 `comments` 数组，通过 `post.id` 关联过滤。
- 删除/恢复操作均为即时生效（前端内存），实际应调用内容管理接口并记录操作日志。

---

### 6.6 评论区管理

**用户场景**
平台管理员发现某条评论存在违规内容（如广告、辱骂），需要单独处置该评论而不影响帖子本身。

**前置条件**
- 已展开帖子详情面板，看到评论区。

**需求描述**
- 评论区以列表形式展示该帖子下的所有评论。
- 每条评论包含：
  - 评论作者（加粗）
  - 状态标签（如"正常"、"已删除"）
  - 评论内容
  - 操作按钮："删除评论"或"恢复评论"
- 点击操作按钮即时更新评论状态。

**后置条件**
- 评论状态更新，评论区列表同步刷新。

**补充说明**
- 评论状态与帖子状态共用 `nForum()` 状态映射。
- 当前为硬状态切换，实际生产环境应支持填写删除原因、申诉恢复等更完善的流程。

## 8. 备注

- 当前实现为前端静态原型，案例审核和论坛管理操作仅修改内存数据。
- 案例审核的"资料清单"为占位展示，实际应支持图片预览和缩略图查看。
- 论坛处理的评论区目前只展示评论内容和状态，实际应支持查看更多上下文（如评论层级、被回复对象）。
- 移动端的内容审核适合处理简单明确的通过/驳回/删除操作，对于有争议或需要多人复核的内容，建议引导至网页端处理。
- 内容审核操作应记录完整的操作日志（操作人、时间、原因），当前前端原型未实现此功能。
