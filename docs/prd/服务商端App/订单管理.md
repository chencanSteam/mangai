# 服务商端App — 订单管理

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 订单管理 |
| **页面入口** | `tab=orders` |
| **对应原型** | 用户端 App 页面原型 |
| **页面类型** | 列表 + 详情 + 表单 |
| **角色权限** | 已入驻服务商 |

---

## 2. 页面概述

订单管理是服务商端App的核心业务页面，承载门店从「接单」到「完工验收」的全流程操作。页面采用「顶部Tab筛选 + 中间订单列表 + 选中项展开详情」的三段式布局，服务商可在同一页面内完成订单浏览、接单排期、施工跟进、完工提交和验收跟踪，无需频繁跳转。

---

## 3. 功能描述

本页面核心功能包括：订单多状态筛选、订单列表浏览、订单详情查看、接单/拒单操作、完工资料提交、客户验收跟进。

---

## 4. 功能分析

- **订单状态筛选**：支持全部订单、待接单、施工中、待验收、已完成五种状态快速切换。
- **订单列表展示**：按车辆、服务、用户、状态展示订单摘要，支持点击选中。
- **订单详情查看**：展开显示用户、电话、车辆、服务、预约时间、预计工时、当前状态等完整信息。
- **接单与排期**：对待分配订单执行接单，填写排期时间和说明。
- **拒单与重派**：对待分配订单执行拒单，填写拒单原因，平台介入重派。
- **完工提交**：对施工中订单填写完工说明、上传图片、设置验收提醒。
- **验收跟进**：对待验收订单查看客户验收说明并跟进。

## 6. 功能详细说明

### 6.1 订单状态筛选

**用户场景**
服务商需要根据订单所处阶段快速定位需要处理的订单，避免在大量历史订单中翻找。

**前置条件**
- 页面已加载，服务商至少存在一笔关联订单

**需求描述**
1. 页面顶部展示子Tab切换栏，包含5个筛选条件：
   - `全部订单`（id: `all`）
   - `待接单`（id: `pending`）
   - `施工中`（id: `processing`）
   - `待验收`（id: `acceptance`）
   - `已完成`（id: `completed`）
2. 默认选中 `pending`（待接单）。
3. 切换Tab时重新渲染订单列表，并自动选中该状态下的第一条订单。

**后置条件**
Tab切换后，列表和详情区同步更新。

**补充说明**
- 各状态对应的数据过滤逻辑由 `getProviderAllOrders()` 配合 `nOrder(item.status)` 完成。
- 「已完成」Tab 同时包含「售后中」状态的订单。

---

### 6.2 订单列表展示

**用户场景**
服务商在确定筛选条件后，浏览当前状态下的所有订单，选择需要处理的一条。

**前置条件**
已完成状态筛选。

**需求描述**
1. 以纵向列表展示订单卡片，每张卡片包含：
   - **车辆信息**（加粗主标题，左对齐）
   - **状态标签**（右对齐，如「待接单」「施工中」）
   - **用户与电话**（`用户 / 138****0000`，待接单状态下电话脱敏）
   - **服务项目**（如「全车改色膜施工」）
2. 当前选中的订单卡片高亮（`active` 类）。
3. 选中卡片下方自动展开该订单的详情面板。
4. 若当前状态下无订单，展示空状态：`当前暂无订单` + `新的派单或施工单会出现在这里。`

**后置条件**
点击卡片后，该订单被标记为选中，详情面板展开。

**补充说明**
- 电话脱敏规则：`(\d{3})\d{4}(\d{4})` → `$1****$2`，仅在「待接单」Tab生效。

---

### 6.3 订单详情查看

**用户场景**
服务商选中某笔订单后，需要查看完整的订单信息，以决定下一步操作。

**前置条件**
已选中某条订单。

**需求描述**
1. 以 `admin-detail-card` 面板展示订单详情，英文标签 `Order Workbench`，标题为订单号。
2. 键值对列表展示以下字段：
   - **用户**：`item.user`
   - **联系电话**：待分配状态脱敏，其他状态展示完整号码
   - **车辆**：`item.vehicle`
   - **服务项目**：`item.service`
   - **预约安装时间**：`item.appointment`
   - **预计工时**：`providerEstimateDuration(item)`（根据服务类型智能估算）
   - **当前状态**：`providerOrderViewStatus(item, "all")`
   - **售后状态**：仅在「已完成」或「售后中」状态下展示
3. 面板底部根据状态渲染操作按钮（见后续功能点）。

**后置条件**
详情面板展开，操作按钮可用。

**补充说明**
- 预计工时估算规则：车衣/改色 → 2-3天；轮毂/刹车 → 1天；内饰/氛围灯 → 1-2天；默认 → 0.5-1天。

---

### 6.4 接单与排期

**用户场景**
服务商收到新派单后，确认可以承接，需要填写排期时间并接单。

**前置条件**
订单状态为「待分配」或「处理中」，且未被拒单。

**需求描述**
1. 详情面板展示「接单」和「拒单」两个按钮。
2. 点击「接单」弹出模态对话框（`renderProviderDialog`，type: `accept`）：
   - 展示订单摘要（订单号 + 车辆 + 服务）
   - **排期时间**：`datetime-local` 输入框，默认值为订单预约时间或 `2026-04-09T10:00`
   - **排期说明**：文本输入框，默认值为 `已完成排期安排，建议客户提前 30 分钟到店`
3. 点击「确认接单」后：
   - 订单状态更新为「施工中」
   - 预约时间更新为排期时间
   - 订单进度更新为 `门店已接单，排期 xxx 入场施工`
   - 关闭对话框，切换到「施工中」Tab

**后置条件**
订单进入施工中状态，客户端同步更新进度。

**补充说明**
- 接单后订单会从「待接单」Tab消失，出现在「施工中」Tab。

---

### 6.5 拒单与重派

**用户场景**
服务商因排期已满或其他原因无法承接某笔订单，需要提交拒单原因，由平台重新分配。

**前置条件**
订单状态为「待分配」或「处理中」。

**需求描述**
1. 点击「拒单」弹出模态对话框（`renderProviderDialog`，type: `reject`）：
   - 展示订单摘要
   - **拒单原因**：多行文本输入框，默认值为 `当前排期已满，建议平台重新分配。`
2. 点击「提交拒单」后：
   - 订单状态恢复为「待分配」
   - 订单服务商改为「平台重派中」
   - 记录拒单原因和拒单门店
   - 平台介入状态标记为「待重派」
   - 用户端仍显示「待接单」，避免体验中断
3. 对话框关闭，页面提示拒单成功。

**后置条件**
订单回到平台待分配池，平台运营人员收到重派提醒。

**补充说明**
- 拒单后该订单在服务商端标记为 `providerRejectStatus = "已拒单"`，列表中显示「已拒单」。

---

### 6.6 完工提交

**用户场景**
服务商完成施工后，需要提交完工资料（说明、图片、验收提醒），等待客户验收。

**前置条件**
订单状态为「施工中」。

**需求描述**
1. 详情面板展示「提交完工」按钮。
2. 点击后展开完工表单（`renderProviderCompleteForm`）：
   - **完工说明**：多行文本，默认值为 `施工已完成，外观与功能已复检，交付前已与客户确认项目清单。`
   - **上传图片**：文件选择器，支持施工完成图、交付图、细节图，最多9张
   - **提醒客户验收**：文本输入框，默认值为 `请客户重点确认外观细节、功能联调与随车物品`
3. 点击「确认提交完工」后：
   - 订单状态更新为「待验收」
   - 订单进度更新为完工说明 + 图片数量 + 验收提醒
   - 自动切换到「待验收」Tab

**后置条件**
订单进入待验收状态，客户端收到验收提醒。

**补充说明**
- 图片上传为前端模拟，实际仅统计文件数量，未真实上传。

---

### 6.7 验收跟进

**用户场景**
服务商提交完工后，客户尚未验收，服务商需要查看验收说明并跟进客户。

**前置条件**
订单状态为「待验收」。

**需求描述**
1. 详情面板展示「查看客户验收说明」按钮。
2. 点击后更新订单进度为 `已与客户确认验收时间，等待客户完成验收`。
3. 页面提示已更新客户验收跟进说明。

**后置条件**
订单进度更新，便于后续跟踪。

**补充说明**
- 该操作为轻量级跟进，不涉及状态变更。

---

## 8. 备注

- 当前实现为前端静态原型，所有订单状态变更仅在内存和 mock 数据中生效，刷新页面后恢复初始状态。
- 电话脱敏仅作用于「待接单」Tab，其他状态下展示完整号码，便于施工沟通。
- 完工表单支持文件多选，但实际未实现真实上传逻辑。
