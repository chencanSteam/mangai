# 服务商端App — 消息中心

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 消息中心 |
| **页面入口** | `tab=messages` |
| **对应原型** | 用户端 App 页面原型 |
| **页面类型** | 列表 + 即时对话 |
| **角色权限** | 已入驻服务商 |

---

## 2. 页面概述

消息中心是服务商与客户、平台进行即时沟通的入口。页面采用「会话列表 + 聊天窗口」的两级结构：首页展示所有消息会话的摘要列表和系统通知，点击会话后进入该会话的聊天详情页，支持文本消息发送和多媒体附件上传。系统通知以特殊视觉样式高亮展示，确保重要平台消息不被遗漏。

---

## 3. 功能描述

本页面核心功能包括：消息会话列表浏览、系统通知展示、即时对话（聊天）、消息发送、附件上传、已读状态管理。

---

## 4. 功能分析

- **消息会话列表**：展示所有与客户或平台的消息会话，包含会话标题、最新消息预览、时间、状态标签。
- **系统通知展示**：顶部展示未读系统通知，使用醒目的橙红色边框高亮。
- **即时对话**：进入会话后展示完整聊天记录，区分「门店」和「客户」消息气泡。
- **消息发送**：支持输入文本消息并实时发送。
- **附件上传**：支持发送图片、视频、PDF、Word等附件。
- **已读状态**：加载消息中心时自动标记所有通知为已读。

## 6. 功能详细说明

### 6.1 消息会话列表

**用户场景**
服务商需要了解有哪些客户或平台会话需要回复，通过最新消息预览判断优先级。

**前置条件**
- 页面已加载，存在至少一条消息会话数据

**需求描述**
1. 页面以 `user-message-page` 容器包裹，顶部可展示操作反馈提示。
2. 系统通知区（如有）：
   - 展示 `getNotificationsForRole("provider")` 获取的系统通知
   - 每条通知以特殊卡片展示：背景色 `rgba(255,106,0,0.06)`，左侧边框 `3px solid #ff6a00`
   - 包含通知标题、时间、内容摘要
3. 会话列表以 `provider-chat-shell` 容器展示，每条会话为可点击按钮：
   - **会话标题**：`item.title`（如客户姓名或平台客服）
   - **最新消息预览**：`item.preview`
   - **时间**：`item.time`
   - **状态标签**：`item.status`（如「正常」「沟通中」「已处理」）
4. 加载页面时自动调用 `markNotificationsRead("provider")` 标记通知为已读。

**后置条件**
点击会话后进入该会话的聊天详情页。

**补充说明**
- 若当前无任何会话，列表区域为空（当前 mock 数据始终有数据）。
- 系统通知与消息会话数据来源不同，通知来自 `notifications`，会话来自 `fallback.providerMessages`。

---

### 6.2 即时对话（聊天详情页）

**用户场景**
服务商需要与客户就施工细节、预约时间、交付事项等进行一对一沟通。

**前置条件**
已从会话列表中选中某条会话。

**需求描述**
1. 聊天详情页以 `provider-chat-panel` 容器展示，包含：
   - **聊天头部**：返回按钮、英文标签 `Realtime Chat`、会话标题、状态标签
   - **消息气泡区**：按时间顺序展示所有历史消息
   - **消息输入区**：底部固定输入栏
2. 消息气泡样式：
   - 「门店」发送的消息（`from === "provider"`）：右侧对齐，带 `is-self` 类，标签显示「门店」
   - 「客户」发送的消息：左侧对齐，标签显示「客户」
   - 每条消息包含：发送者角色、消息内容、发送时间
3. 返回按钮点击后回到会话列表，清空当前选中会话。

**后置条件**
可继续发送新消息或返回列表。

**补充说明**
- 消息数据存储在 `fallback.providerMessages` 数组的 `messages` 子数组中。

---

### 6.3 消息发送

**用户场景**
服务商在聊天中需要回复客户咨询或主动告知施工进度。

**前置条件**
已进入某条会话的聊天详情页。

**需求描述**
1. 底部输入栏以 `provider-chat-composer` 表单展示，包含：
   - **附件按钮**：文件选择器，支持 `image/*, video/*, .pdf, .doc, .docx`，可多选
   - **文本输入框**：`name="chatMessage"`，placeholder 为 `输入消息并实时发送`
   - **发送按钮**：主按钮样式
2. 点击发送或回车后提交表单（`handleProviderChatSubmit`）：
   - 若文本和附件均为空，不执行发送
   - 获取当前时间（HH:mm）作为消息时间
   - 若有附件，消息内容追加附件文件名列表（最多显示3个，超出显示「等 N 个文件」）
   - 将新消息追加到该会话的 `messages` 数组
   - 更新会话的 `preview` 和 `time` 为最新消息
   - 更新会话状态为「沟通中」
3. 发送成功后页面提示 `xxx 已发送新消息。`

**后置条件**
新消息出现在聊天气泡区底部，会话列表中的预览和时间同步更新。

**补充说明**
- 附件上传为前端模拟，实际仅读取文件名，未真实上传服务器。
- 消息发送后页面即时重新渲染，无网络延迟模拟。

## 7. 数据源

| 数据项 | 来源变量 | 来源文件 |
|--------|---------|---------|
| 消息会话列表 | 业务数据 | 原型数据 |
| 系统通知 | `getNotificationsForRole("provider")` | `原型数据` / `mobile-app.js` |
| 会话消息记录 | `item.messages`（`fallback.providerMessages` 子数组） | 原型数据 |
| 通知已读状态 | `markNotificationsRead("provider")` | 页面逻辑 |

---

## 8. 备注

- 当前实现为前端静态原型，所有消息数据来自 `原型数据`，消息发送仅在内存中生效。
- 系统通知的视觉高亮（橙红边框）确保平台重要消息优先被服务商感知。
- 附件支持多种文件类型，但实际仅作文件名展示，未实现真实文件上传与预览。
- 聊天界面区分「门店」和「客户」两种角色气泡，符合主流即时通讯的视觉习惯。
