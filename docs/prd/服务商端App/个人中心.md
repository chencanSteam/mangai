# 服务商端App — 个人中心

## 1. 页面基本信息

| 项目 | 说明 |
|------|------|
| **页面名称** | 个人中心 / 我的 |
| **页面入口** | `tab=me` |
| **对应原型** | 用户端 App 页面原型 |
| **页面类型** | 信息展示 + 表单编辑 |
| **角色权限** | 已入驻服务商 |

---

## 2. 页面概述

个人中心是服务商管理门店信息与查看营业数据的入口。页面分为「营业情况」和「门店资料」两个子Tab：「营业情况」复用首页的经营数据看板，展示门店累计订单、施工中订单、待验收、采购跟进等核心指标；「门店资料」展示门店与账号的完整信息，并支持编辑更新，更新后需平台重新审核。

---

## 3. 功能描述

本页面核心功能包括：营业数据查看、门店资料展示、门店资料编辑、联系平台客服、审核状态跟踪。

---

## 4. 功能分析

- **营业情况子Tab**：展示门店营业统计卡片和今日营业概览面板。
- **门店资料子Tab**：以键值对形式展示门店名称、联系人、地址、主营能力、审核状态、门店状态。
- **门店资料编辑**：展开表单编辑联系人、门店地址、主营能力，保存后触发平台重新审核。
- **联系平台客服**：一键跳转至消息中心与平台客服建立会话。

## 6. 功能详细说明

### 6.1 营业情况

**用户场景**
服务商需要随时了解门店的整体经营表现，包括订单处理进度和采购跟进情况。

**前置条件**
用户已切换至 `tab=me` 且 `subTab=business`。

**需求描述**
1. 页面结构与首页「门店工作台」中的营业情况一致（复用 `页面渲染`）。
2. 顶部展示英文标签 `Business Overview` 和中文标题 `门店营业情况`。
3. 2×2 统计卡片：
   - **累计完成订单**：已完成状态的订单总数
   - **施工中订单**：施工中状态的订单总数
   - **待客户验收**：待验收状态的订单总数
   - **采购跟进中**：未签收的采购记录数量
4. 今日营业概览面板：
   - 门店营业状态（正常营业 / 休息中 / 已下线）
   - 案例展示数量
   - 累计订单数量

**后置条件**
纯展示，无状态变更。

**补充说明**
- 营业情况子Tab为只读面板，所有编辑操作在「门店资料」子Tab中完成。

---

### 6.2 门店资料展示

**用户场景**
服务商需要确认当前门店在平台登记的信息是否准确，并了解审核和营业状态。

**前置条件**
用户已切换至「门店资料」子Tab（默认）。

**需求描述**
1. 以 `admin-detail-card` 面板展示，英文标签 `Store Profile`，中文标题 `门店与账号信息`。
2. 键值对列表展示以下字段：
   - **门店名称**：`store.name`
   - **联系人**：`store.contact`
   - **门店地址**：`store.address`，若不存在则展示 `${city}${district}改装产业园 A3-201`
   - **主营能力**：`store.specialties`
   - **审核状态**：`nAudit(store.auditStatus)`（已通过 / 待审核 / 未通过）
   - **门店状态**：`nProvider(store.status)`（正常营业 / 休息中 / 已下线）
3. 面板底部提供两个操作按钮：
   - 「更新门店资料」（二级按钮）：点击展开/收起编辑表单
   - 「联系平台客服」（主按钮）：点击跳转消息中心

**后置条件**
点击「更新门店资料」展开编辑表单；点击「联系平台客服」跳转 `tab=messages`。

**补充说明**
- 门店资料来源于 `getProviderStore()`，返回审核已通过的服务商或第一条服务商数据。

---

### 6.3 门店资料编辑

**用户场景**
服务商变更了联系人、门店地址或主营业务范围，需要在平台更新信息以保持准确。

**前置条件**
已点击「更新门店资料」按钮展开编辑表单。

**需求描述**
1. 以 `provider-complete-form` 表单展示（`renderProviderProfileForm`），包含三个字段：
   - **联系人**：文本输入框，`name="providerContact"`，必填
   - **门店地址**：文本输入框，`name="providerAddress"`，必填，默认值为当前地址
   - **主营能力**：文本输入框，`name="providerSpecialties"`，必填
2. 底部操作按钮：「保存资料」（主按钮）、「取消」（二级按钮）。
3. 点击「保存资料」后（`handleProviderProfileSubmit`）：
   - 校验三个字段均不为空
   - 更新 `store.contact`、`store.address`、`store.specialties`
   - 将审核状态重置为「待审核」
   - 收起编辑表单
   - 页面提示：`门店资料已更新，平台将重新审核，审核通过后方可正常接单。`

**后置条件**
门店资料更新，审核状态变为「待审核」，需等待平台运营人员重新审批。

**补充说明**
- 资料更新后服务商的接单权限可能受影响，需平台审核通过后方可恢复正常。
- 取消编辑仅收起表单，不保存任何修改。

---

### 6.4 联系平台客服

**用户场景**
服务商在经营过程中遇到问题（如订单异常、结算疑问、系统故障），需要联系平台客服寻求帮助。

**前置条件**
处于「门店资料」子Tab。

**需求描述**
1. 点击「联系平台客服」按钮。
2. 触发 `state.tab = "messages"`，跳转至消息中心Tab。

**后置条件**
页面切换至消息中心，服务商可与平台客服发起会话。

**补充说明**
- 该操作为纯路由跳转，不自动创建新的客服会话。

## 7. 数据源

| 数据项 | 来源变量 | 来源文件 |

| 采购记录 | `getProviderPurchaseRecords()` | `原型数据` / `mobile-app.js` |

| 结算数据 | `getProviderSettlementRows()` | `原型数据` / `mobile-app.js` |

---

## 8. 备注

- 当前实现为前端静态原型，门店资料编辑仅在内存中生效，刷新页面后恢复初始 mock 数据。
- 资料更新后审核状态重置为「待审核」，这是一个关键业务逻辑，确保平台能持续把控服务商资质。
- 营业情况子Tab与个人中心的其他功能解耦，便于后续扩展更多子Tab（如「结算管理」、「员工权限」等）。
